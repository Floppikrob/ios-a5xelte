# A5XELTE migration from the SWEET donor

The donor README and `NOTES.md` describe a demonstrated Redmi Note 10 Pro (`sweet`) iOS 16 port. They are source and sequencing references. This document is the Samsung SM-A510F decision record. `A5XELTE_PROGRESS.md` records build results, TWRP readback and user-visible behavior separately.

| Component | A5XELTE status | When to adapt or retire SWEET code |
| --- | --- | --- |
| BOOT handoff and loader | Samsung BOOT p10 with stock DTBH; Exynos7580 EL1 handoff and 4 KiB loader are device tested. | A5XELTE uses `shim/a5xelte/` now. Do not use Xiaomi `fastboot boot`, ABL/QCOM register writes or donor `shim/build.sh` on Samsung. Keep the donor files as a comparison until A5XELTE has an independently reproducible build and recovery path. |
| XNU page size and board target | A5XELTE XNU entered and executed an instruction after enabling the 4 KiB MMU. | `0082` onward provides the Samsung build path. Remove the temporary donor `SWEET` compile definition only after every shared compile-time facility has an A5XELTE replacement and the resulting kernel is built and reaches the same device checkpoint. |
| Early display and console | Exynos DECON/DSIM handoff and visible loader text, XNU entry, and post-MMU blocks are device verified. General XNU console text is still unverified. | Use `mainline/drivers/exynos7580-drm-handoff.c` for register/clock behavior. Keep the tiny assembly/loader stage display until the XNU framebuffer console produces visible messages. Do not import Qualcomm framebuffer or IOMFB assumptions. |
| Interrupts and timer | A5XELTE ADT names GICv2 and virtual timer INTID 27. Runtime IRQ/tick behavior is unverified. | Prove CPU0 timer and interrupt handling before adapting SMP. SWEET GICv3/19.2 MHz/PSCI topology cannot be copied as hardware facts. |
| Storage and root | No eMMC XNU driver or iOS root-device test. Linux USERDATA remains in use. | Adapt from Samsung/Lineage/Linux eMMC references after visible panic/console is reliable. Only then design a root image fitting this device; donor UFS and `fastboot flash userdata` instructions never apply verbatim. |
| Input, display services and userland | No A5XELTE touch, keys, IOSurface, IOMFB or iOS userland boot proof. | Port hardware interfaces one at a time after kernel boot and root access. Reuse donor userland-facing contracts only with device-side verification. Do not call the donor's SpringBoard result an A5XELTE result. |
| Documentation | README now labels the SWEET section as donor reference; this map and A5XELTE notes state current facts. | Update the A5XELTE README summary at each proven milestone. Keep donor `NOTES.md`, `docs/QEMU_TESTING.md` and donor examples intact as historical references until their replacements are tested, then move them under a donor-specific path in a dedicated cleanup commit. |

SWEET-specific files should be removed from the active A5XELTE build in stages: first remove hardware assumptions from the selected A5XELTE target; next confirm each replacement builds and boots to the previous checkpoint; finally remove unused donor files and rename compatibility symbols. Deleting donor files before that loses working reference code and can hide build dependencies. The repository can retain donor history even after the A5XELTE default path is independent.
